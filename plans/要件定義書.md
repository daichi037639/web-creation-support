# 要件定義書 — Webサイト制作支援サービス

バージョン: 0.4（フィードバック反映）
作成日: 2026-06-28

---

## 1. サービスの目的

良い商品・想いを持ちながら、Webサイト制作やマーケティングに取り組めていない
老舗企業・個人事業者が、**初心者でも一人で前に進められる状態**をつくる。

単にツールを紹介するのではなく、このサービスの上で**計画から公開まで完結**させる。
「何から考えればいいか」「どんな型で進めればいいか」をウィザードで誘導しながら、
最終的には**自然言語でサイトを生成・Vercelで公開**するところまでつなぐ。

---

## 2. ターゲットユーザー

### メインターゲット
- 老舗企業・個人事業者の経営者・担当者（30〜60代）
- 商品・サービスには自信があるが、Webやマーケティングは未経験
- 外注費用をかけられない、またはかけたくない

### セカンダリターゲット
- 親族・知人の事業を手伝っている若い世代（石原さんのような立場）
- 地方の小規模事業者

### ユーザーが抱える課題（Jobs To Be Done）

| 課題 | 具体例 |
|------|--------|
| 何から始めればいいかわからない | 「ホームページが必要とは思うが、最初に何をすればいいか不明」 |
| 型・手順がわからない | 「要件定義とは何か。どういう順序で考えるのか知らない」 |
| 外注は敷居が高い | 「業者に頼むとお金がかかる。でも自分でできる気もしない」 |
| ツールがあっても使えない | 「STUDIOやWordPressを試したが、何を作ればいいかわからなかった」 |

## 3. ユーザーフロー（STEP 0〜7）

ウィザード形式（順序があるフォーム画面の連続）を基本とする。
各画面でAIが質問を投げかけ、ユーザーが答えることで必要情報を引き出す。
困ったときは画面内のAIチャットを呼び出して自然言語で相談できる。

```
STEP 0: このサービスでできることを確認する（ゴールと全体フローの説明）
STEP 1: 事業・商品の棚卸し（何を売っているか、強みは何か）
STEP 2: ターゲット顧客の整理（誰に届けたいか、どんな悩みを解決するか）
STEP 3: 伝えたいメッセージの言語化（一番伝えたいことは何か）
STEP 4: サイト構成の設計（どんなページが必要か、何を載せるか）
STEP 5: コンテンツ準備（文章・写真の用意。AIが草案を生成）
STEP 6: サイト生成（STEP 1〜5の情報をもとにAIがコードを生成。自然言語で修正指示を出しながら反復）
STEP 7: 公開（GitHub + Vercel アカウントを作成し、手順ガイドに沿ってデプロイ）
```

### STEP 0〜5（計画）の各画面要素
- 「なぜこのステップが必要か」の解説テキスト（型のインプット）
- AIからの質問 + ユーザーの回答フォーム
- AIチャットへの呼び出しボタン（いつでも相談できる）
- 次のステップへのチェックリスト

### STEP 6（サイト生成）の仕様
- **本サービス自体**：Next.js（App Router）で構築
- **生成するサイトのコード形式**：STEP 4 で確認した希望機能の複雑さに応じてシステムが自動判定・提案
  - シンプルなサイト（会社紹介・商品紹介・ギャラリーなど）→ 静的 HTML/CSS/JS
  - 問い合わせフォーム・予約・DB連携など → Next.js
- リアルタイムプレビュー（iframe）で確認しながら反復
- ページ数はMVPでは3〜5ページ程度

### STEP 7（公開）の仕様
- ユーザー自身が GitHub + Vercel アカウントを作成し、自分のアカウントとして管理する
- このサービスを使わなくなっても管理できる自立性を優先する
- サービスはアカウント作成〜デプロイまでの手順をわかりやすくガイドする

## 6. 主要機能（MVP スコープ）

| 機能 | 優先度 | 備考 |
|------|--------|------|
| ウィザードフロー（STEP 0〜5） | Must | 計画ステップの核心 |
| AIチャット（呼び出し式） | Must | ウィザード内の「相談窓口」 |
| AIサイトコード生成（STEP 6） | Must | 生成ステップの核心 |
| リアルタイムプレビュー（iframe） | Must | バイブコーディングに必須 |
| デプロイガイド（STEP 7） | Must | 公開ステップの核心 |
| 進捗の保存・再開 | Should | ローカルストレージで対応（MVP） |
| ユーザー登録・ログイン | Won't（MVP） | 拡張できる設計にしておく |

## 8. 技術スタック（案）

| 領域 | 採用候補 | 理由 |
|------|---------|------|
| フロントエンド | Next.js (App Router) | AIとの相性・ドキュメント充実 |
| スタイリング | Tailwind CSS | 枯れたツール・AIが精度高く書ける |
| AI（ガイド・生成） | Claude API (Sonnet 4.5以降) | 日本語精度・ストリーミング・コード生成 |
| DB / Auth | Supabase | 認証の後付けが容易。MVP時はAuth無効 |
| ホスティング（本体） | Vercel | Next.jsとの相性 |
| 生成サイトのデプロイ | Vercel API | プログラマティックなデプロイが可能 |

### 設計方針
- **認証は後付けできる設計**にしておく。MVP時点ではゲスト利用のみだが、
  Supabaseの認証を後から差し込める構造にする
- CLAUDE.md・要件定義書は開発を進めながら随時ブラッシュアップしていく（生きたドキュメント）

---

## 9. 非機能要件

- **モバイル対応**：ターゲットがスマホから使う可能性が高い
- **日本語のみ**：MVP時点では日本語専用
- **レスポンス速度**：AIの回答はストリーミングで表示（体感速度を上げる）
- **進捗の保存**：ローカルストレージで中断・再開（MVP）→ 将来はDBへ移行
