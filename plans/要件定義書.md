# 要件定義書 — Webサイト制作支援サービス

バージョン: 0.16（LOG-016：Visual Editor（OSS版 Puck）。D&D並び替え・クリック編集・AI修正の統合）
作成日: 2026-06-28
最終更新: 2026-08-10

---

## 1. サービスの目的

良い商品・想いを持ちながら、Webサイト制作やマーケティングに取り組めていない
老舗企業・個人事業者が、**初心者でも一人で前に進められる状態**をつくる。

単にツールを紹介するのではなく、このサービスの上で**計画から公開まで完結**させる。
「何から考えればいいか」「どんな型で進めればいいか」をウィザードで誘導しながら、
最終的には**自然言語でサイトを生成・Vercelで公開**するところまでつなぐ。

---

## 2. ターゲットユーザー

### メインターゲット
- 老舗企業・個人事業者の経営者・担当者（30〜60代）
- 商品・サービスには自信があるが、Webやマーケティングは未経験
- 外注費用をかけられない、またはかけたくない

### セカンダリターゲット
- 親族・知人の事業を手伝っている若い世代（石原さんのような立場）
- 地方の小規模事業者

### ユーザーが抱える課題（Jobs To Be Done）

| 課題 | 具体例 |
|------|--------|
| 何から始めればいいかわからない | 「ホームページが必要とは思うが、最初に何をすればいいか不明」 |
| 型・手順がわからない | 「要件定義とは何か。どういう順序で考えるのか知らない」 |
| 外注は敷居が高い | 「業者に頼むとお金がかかる。でも自分でできる気もしない」 |
| ツールがあっても使えない | 「STUDIOやWordPressを試したが、何を作ればいいかわからなかった」 |

## 3. ユーザーフロー（STEP 0〜7）

ウィザード形式を基本とするが、**順番の強制はしない**（[LOG-009](./検討事項ログ.md)）。
STEPは「考える順序のおすすめ」であり、未入力のままいつでも次へ進める。
未入力項目はAI生成時に補完される前提とし、後からいつでも埋められる導線を用意する。
困ったときは画面内のAIチャットを呼び出して自然言語で相談でき、
チャットは**それまでの回答をすべて把握した状態**で応答する。

```
STEP 0: このサービスでできることを確認する（ゴールと全体フローの説明）
STEP 1: 事業・商品の棚卸し（何を売っているか、強みは何か）
STEP 2: ターゲット顧客の整理（誰に届けたいか、どんな悩みを解決するか）
STEP 3: 伝えたいメッセージの言語化（一番伝えたいことは何か）
STEP 4: サイト構成の設計（どんなページが必要か、何を載せるか）
STEP 5: コンテンツ準備（文章の用意とAI草案。実素材写真のアップロード＝生成サイトへ実掲載）
STEP 6: サイト生成（STEP 1〜5の情報をもとにAIがコードを生成。自然言語で修正指示を出しながら反復）
STEP 7: 公開（GitHub + Vercel アカウントを作成し、手順ガイドに沿ってデプロイ）
```

### STEP 0〜5（計画）の各画面要素
- 「なぜこのステップが必要か」の解説テキスト（型のインプット）
- AIからの質問 + ユーザーの回答フォーム
- AIチャットへの呼び出しボタン（いつでも相談できる）
- 次のステップへのチェックリスト

### STEP 1〜3（言語化パート）の入力体験

要件定義未経験者の入力負担を下げるため、固定フォームではなく**カード式**とする。
2026-07-14 のフィードバックを受けてリニューアル（[LOG-009](./検討事項ログ.md)）：

- 質問1つ = カード1枚。状態は「未入力 / 入力済み」の2つ
  （「あとで考える（保留）」は廃止。未入力のまま進めることと意味が重複していたため）
- **必須カードは置かない**。未入力でもステップをクリアでき、
  AI生成時は「未定（AIが補完提案する）」として扱う。
  入力が推奨されるカードには「おすすめ」バッジのみ表示する
- 各カードに**「AIと一緒に考える」ボタン**を設置。その質問のコンテキストと
  **それまでの全回答**を持ったAIチャットが開き、対話しながら答えを言語化できる
- AIチャットは会話から引き出した内容を**構造化してカードへ書き込める**
  （tool use / structured output。書き込み前にユーザーが確認する）
- **「まとめて話す」一括入力**：1つの大きな自由入力欄に事業のことを思いつくまま
  書いて（スマホではOSの音声入力を利用）もらい、AIが各カードへ振り分ける。
  **パンフレット・チラシ・メニューなどの資料写真（最大3枚）**からも同様に読み取れる
- **AI音声インタビューモード**：チャットの「🎙 AIインタビューで進める」から開始。
  全画面の音声対話UIで、AIが未回答の質問を音声でやさしく聞き、声で答えるだけでカードが
  埋まっていく（OpenAI Realtime API + WebRTC。低遅延・割り込み対応。[LOG-011](./検討事項ログ.md)）。
  回答はAIが構造化してカードへ即保存し、トーストで通知（あとから確認・修正できる）。
  マイクが使えない環境では従来のテキストインタビューへフォールバックする
- すべての入力は**即時自動保存**され、途中で離脱してもいつでも再開できる。
  保存されていることを画面上に明示する。進捗はサーバー（Supabase）にも自動同期され、
  「入力状況」パネルの**引き継ぎリンク**で別の端末からも続きを開ける

### 未入力を後から埋める導線

- 全ステップ横断の**回答状況一覧**から未入力カードへ直接ジャンプできる
- STEP 6 のサイト生成前に「未入力のままAIにおまかせする項目」を一覧で確認する

### 業態・業界プロファイル（STEP 1 冒頭）

STEP 1 の最初に、タップ選択のみの2問を置く：

- **業態**：実店舗 / オンライン販売 / 両方 / 訪問・出張型
- **業界**：飲食店 / 小売・物販 / 食品・農産物の生産販売 / 美容・サロン / 宿泊・観光 /
  教室・スクール / 士業・専門サービス / 製造業 / その他（自由入力）

選択した業態・業界に応じて、以降の質問カードの表示有無・文言を出し分ける
（例：飲食店には「顧客の悩みや不満」ではなく「お客さまはどんな気分・場面でお店を選ぶか」と聞く）。
MVP は静的な質問バンク + 業界別言い換えで実装する（[検討事項ログ LOG-005](./検討事項ログ.md)）。

### ゲーム演出（ライト）

「クリアしていく」感覚で楽しく進められるよう、以下のライトな演出を入れる
（レベル・ポイント制などの本格的なゲーミフィケーションはやらない。[LOG-006](./検討事項ログ.md)）：

- ヘッダーに回答済みカード数ベースの**全体完成度メーター**（%）
- ステップ内に「カード n / m 枚」の収集感表示
- ステップクリア時のお祝い演出（CSSアニメーションのみ）

### STEP 6 冒頭「デザインの好みを選ぶ」（/wizard/design）

サイト生成の直前に、参考デザイン事例からAIが選んだ**デザイン候補3案**を画像付きカードで提示する
（[LOG-008](./検討事項ログ.md)）：

- ここまでの回答（業種・ターゲット・トーン等）をAIが検索条件に整理し、published の参考事例から
  スコアリング + 多様性を考慮して3案を選ぶ
- 候補名は「格調高い老舗の風格」のような初心者向けの方向性名（参考サイト名は出さない）
- 「AIにおまかせ」（最上位案を自動採用）と、選ばずに進む（標準デザイン）も可能
- 選択後、AIが**デザイン設計書**（配色・タイポグラフィ・ファーストビュー・余白・CTA・スマホ方針・
  避ける表現）を作成し、サイト生成プロンプトに反映する
- 参考事例0件・検索失敗時もウィザードは継続できる（標準デザインで生成）

### STEP 6（サイト生成）の仕様

2026-08-10 に **Component-driven generation** へ移行（[LOG-012](./検討事項ログ.md)）：

- **本サービス自体**：Next.js（App Router）で構築
- **生成方式**：AIにHTMLを一括生成させず、(1) Site Brief + Design Tokens、
  (2) ページ・セクション構成（コンポーネント選択とprops）を structured output で判断させる。
  出力は必ず validation（未知コンポーネント除去・defaults補完・stable ID付与）を通す
- **Component Library**：自前の高品質コンポーネント 12カテゴリ・28種
  （`/dev/components` の Showcase で全件確認できる）
- **Design Tokens**：業種別5プリセット + AIによる色・書体・装飾（見出しのあしらい・写真の見せ方・
  区切り線・入場モーション）の上書き。CSS Variables で描画に直結
- **Style Props**：各セクションに token 範囲内のスタイル上書き（背景・余白・揃え・見出しサイズ等）を
  持たせ、同じコンポーネントでも表情を変えられる（テンプレ感の解消。[LOG-013](./検討事項ログ.md)）
- **画像**：実素材（Supabase Storage）/ placeholder を AssetReference で統一。
  写真が無くても崩れず、「用意すると良い写真」を提案として表示する
- **フォント**：厳選18種の日本語 Google Fonts から見出し・本文を別々に選択。AIが提案し、
  生成後はユーザーがピッカーで実フォント表示を見ながら自由に変更できる（[LOG-014](./検討事項ログ.md)）
- **自然言語での部分修正**：「この見出しを短く」「もっと高級感を」等をAIが7操作（内容/スタイル/
  トークン/variant差し替え/並び替え/追加/削除）の最小の1つに変換し、全再生成せず適用。
  プレビューのセクションをクリックして対象を指定でき、直近10回まで「元に戻す」が可能（[LOG-015](./検討事項ログ.md)）
- **Visual Editor**：`/editor`（OSS版 Puck）。左=追加できるコンポーネント／中央=D&Dで並び替え・
  クリックで選択できるプレビュー／右=選択中セクションの設定（文章・写真・見た目の調整）。
  AI修正パネルも右下に常駐。source of truth は SiteData のまま（[LOG-016](./検討事項ログ.md)）
- **プレビュー**：`/preview` を iframe 表示（PC/スマホ切替・別タブ表示・クリックでセクション選択）
- **公開ファイル**：内部表現は React に統一し、公開時に静的HTMLへ書き出す
  （旧「静的HTML / Next.js の自動判定」分岐は廃止）
- ページ数はMVPでは3〜5ページ程度

### STEP 7（公開）の仕様
- ユーザー自身が GitHub + Vercel アカウントを作成し、自分のアカウントとして管理する
- このサービスを使わなくなっても管理できる自立性を優先する
- サービスはアカウント作成〜デプロイまでの手順をわかりやすくガイドする

## 6. 主要機能（MVP スコープ）

| 機能 | 優先度 | 備考 |
|------|--------|------|
| ウィザードフロー（STEP 0〜5、順番強制なし） | Must | 計画ステップの核心。未入力でも進める |
| カード式入力（STEP 1〜3、必須なし） | Must | 入力負担の軽減。保留機能は廃止（LOG-009） |
| 業態・業界プロファイルと質問出し分け | Must | 静的質問バンク + 業界別言い換え |
| 質問ごとの「AIと一緒に考える」 | Must | カードからコンテキスト付きでAIチャットを起動 |
| ゲーム演出（完成度メーター・クリア演出） | Should | ライト演出のみ。レベル制はやらない |
| AIチャット（常駐・全回答を参照） | Must | ウィザード全体に常駐。回答状況を踏まえて相談できる |
| チャットからのカード書き込み（tool use） | Must | AIが会話から回答を抽出しカードへ反映（確認付き） |
| 「まとめて話す」一括入力 | Must | 長文・音声入力（OS機能）をAIがカードへ振り分け |
| 資料写真からのAI読み取り | Must | パンフ・チラシ等の写真（最大3枚）から情報抽出 |
| 実素材アップロード | Should | STEP 5で商品・店舗写真等（最大10枚）をアップロード。AIが種類・キャプションを自動付与（編集可）し、生成サイトに実URLで掲載（[LOG-010](./検討事項ログ.md)） |
| AI音声インタビューモード | Should | AIと音声で会話するだけでカードが埋まる（OpenAI Realtime + WebRTC。[LOG-011](./検討事項ログ.md)）。テキスト版はフォールバックとして継続 |
| 進捗のサーバー同期・端末引き継ぎ | Should | wizard_sessions テーブル（要migration）。引き継ぎリンクで別端末から再開 |
| 回答状況一覧・生成前チェック | Should | 未入力カードへのジャンプ・生成前の最終確認 |
| AIサイトコード生成（STEP 6） | Must | 生成ステップの核心 |
| リアルタイムプレビュー（iframe） | Must | バイブコーディングに必須 |
| デプロイガイド（STEP 7） | Must | 公開ステップの核心 |
| 進捗の保存・再開 | Should | ローカルストレージで対応（MVP） |
| 参考デザイン事例の登録・検索 | Should | 管理者がURLを登録→Claudeが分析+スクリーンショット取得→Supabaseに保存・編集可。ユーザーは業界・タグで検索（[LOG-007](./検討事項ログ.md)） |
| デザインの好み選択 + デザイン設計書 | Should | サイト生成直前に候補3案から選択（おまかせ・スキップ可）。設計書を生成プロンプトへ反映（[LOG-008](./検討事項ログ.md)） |
| 管理者ログイン | Should | Supabase Auth + ADMIN_EMAILS 許可リスト。参考事例の登録用 |
| ユーザー登録・ログイン | Won't（MVP） | 拡張できる設計にしておく |

## 7. MVP 対象外（今後のフェーズ）

- ウィザードのフルSPA化（`/wizard` 1ルートへの統合）
  ※ App Router のクライアント遷移 + layout 常駐でチャット・状態は既に維持されるため、
  ステップページが薄くなったタイミングで実施する（LOG-009）
- 生成サイト用素材の zip 書き出し・ユーザーの GitHub リポジトリへの画像同梱
  （実素材の掲載自体は対応済み。現状は当サービスの Supabase 公開URLをホットリンクする。[LOG-010](./検討事項ログ.md)）
- SNSマーケティングのガイド
- AIによる質問の動的生成（MVPは静的質問バンクで対応）
- 類似サイトの自動調査（参考事例は管理者による手動登録で対応済み）
- 複数ページテンプレートの選択
- チーム・複数ユーザー機能
- 有料プランの課金機能
- 多言語対応
- 生成サイトの継続的な更新管理

## 8. 技術スタック（案）

| 領域 | 採用候補 | 理由 |
|------|---------|------|
| フロントエンド | Next.js (App Router) | AIとの相性・ドキュメント充実 |
| スタイリング | Tailwind CSS | 枯れたツール・AIが精度高く書ける |
| Visual Editor | @measured/puck（OSS・MIT） | D&D編集UI。有料の Puck AI / Cloud は使わない（[LOG-016](./検討事項ログ.md)） |
| AI（ガイド・生成） | Claude API (Sonnet 4.5以降) | 日本語精度・ストリーミング・コード生成 |
| AI（音声インタビュー） | OpenAI Realtime API (gpt-realtime) + WebRTC | speech-to-speech一体型の低遅延音声対話・割り込み対応（[LOG-011](./検討事項ログ.md)） |
| DB / Auth | Supabase | 参考事例DB（RLS有効）+ 管理者認証で利用中。一般ユーザー認証は後付け予定 |
| ホスティング（本体） | Vercel | Next.jsとの相性 |
| 生成サイトのデプロイ | Vercel API | プログラマティックなデプロイが可能 |

### 設計方針
- **認証は後付けできる設計**にしておく。MVP時点ではゲスト利用のみだが、
  Supabaseの認証を後から差し込める構造にする
- CLAUDE.md・要件定義書は開発を進めながら随時ブラッシュアップしていく（生きたドキュメント）

## 9. 非機能要件

- **モバイル対応**：ターゲットがスマホから使う可能性が高い
- **日本語のみ**：MVP時点では日本語専用
- **レスポンス速度**：AIの回答はストリーミングで表示（体感速度を上げる）
- **進捗の保存**：ローカルストレージで即時保存 + Supabaseへ自動同期（引き継ぎリンクで端末またぎ再開）。
  ユーザー認証の導入後はアカウント紐付けへ移行
